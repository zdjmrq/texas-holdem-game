# v1.5.8 算法、界面与验收报告

2026-10-08。重点配置为标准十人桌、起始 5000、盲注 100/200。机器人用程序范围推断、权益模拟、合法下注收益与风险比较，不加载神经网络，也不读取其他人的未公开底牌。

## 当前结论与适用范围

四倍采样候选四个新种子 451001～454001 共 16,384 手确认仅 **+0.02 BB/100，区间 -1.69～+1.72**。此前筛选的 +6.98 未复现，撤下默认启用；其更高计算成本不应无证据让用户承担。第六轮组合的八组独立确认也未获得优势，两个默认开关已撤下。本报告是工作稿。

第三轮纪律候选：两组新种子 411001、412001，16,384 手、512 个洗牌块，相对完整 v1.5.7 的候选团队收益 **+0.13 BB/100**，标准误 0.75，名义 95% 区间 **-1.35～+1.61**。 区间包含零，撤下默认人格调整。风险、精度、全下实现候选仍在测试，本报告是工作稿，尚未交付最终增强版本。

设计目标是更有纪律和压力的对手，不宣称已达到职业牌手或 GTO 水平。与旧版 Bot 的比赛不是对职业真人的验证，也不能外推短牌或所有深度。所有目标候选均限定上述初始配置；有人出局时按当前人数与实际有效深度决策，下一手不更换人格。其他初始配置、短牌沿用已验证策略。

## 默认策略与实验项

已测试施压风格收窄参与范围、谨慎风格提高合理开池比例、防守风格减少弱牌平跟的候选，但独立确认未获优势。内部风格 ID 和名字独立，整桌保持；参数不是强制行动频率，所有动作仍经过合法候选、赔率、对手范围、风险与 EV 比较。

四倍采样独立确认未获得优势，已撤下默认启用。当前所有新增开关均为零，包括 `rankedContinuationWeight`；所有未通过强度确认的候选均仅供显式实验；第七阶段在测试终局跟注收益，不默认启用。不能把已经写出的候选算法说成已交付增强。

新实现的联合付款计算按假设牌、实际跟注概率及边池层级积分赢牌份额与追加额，解决两个平均值相乘的独立性假设；穷举行动分支、不同筹码、平分和精确组合权重数学测试通过。其首次选择 +3.34 BB/100，在独立 16,384 手确认仅 **+0.33 BB/100，区间 -1.38～+2.03**，因此撤下默认启用。数学更精确不自动等于实际更强。

## 页面跳动、悬停和已读提醒

旧版实际 Electron 在 1280×860 下，牌桌高度在 570/592/636/580 间变化；900×600 在 484/512/556/520 间变化。思考点、下注和动作改变座位尺寸，渲染代码与 ResizeObserver 又争用坐标，导致整页重排和滚动位置变化。

现在座位尺寸固定，空下注/动作行保留位置，思考点绝对定位；实测排布函数独占坐标更新。隐藏思考点暂停动画，不在空行继续运行。相同手牌、位置标识和音乐文字复用节点。24 次 Bot 状态切换，两种尺寸都只有一套座位布局；本地和联网渲染均保持桌高与滚动位置。初次开桌的布局计算、发公共牌动画和用户主动滚动不属于 Bot 出手跳动。

真实可见窗口连续三手，通过逐帧牌桌、座位、滚动位置检测；每个街内仅一套几何布局，排除开桌最初两次读数。另验收九个 Bot 在 900×600、1200×700、1280×860 全部位于容器内且不重叠。顶部触发区按工具栏实测高度的 85% 更新，小窗口或滚走顶部后，鼠标进入该区域即可展开，移开收起；展开后工具栏提升到触发层之上。真实鼠标命中检查覆盖 y=20/35/55，并实际点击提示音按钮，避免透明层挡住拖动和按钮。

提醒使用待操作消息编号区分“同一条快照”和“新的行动”。主窗口恢复前台/取得焦点作为已读判据：停止任务栏闪烁、托盘红色动画，之后未处理就切走也不重闪。后台出现新的出手提示或新结算才重新提醒。结算声音仍按每次新弹窗播放一次，尊重静音。真实 Windows IPC 检查了后台 A 闪、前台 A 停、切走 A 不闪、后台 B 重闪，全部通过。

## 信息隔离和一致性

只输入自己的牌、已公开公共牌、位置、筹码和公开行动。未知组合与未来牌从独立未知牌集模拟，不读取实际未发牌堆；不得用模拟未来牌力决定当前是否继续。对手人格、内部计划和隐藏牌不进入公开玩家对象。后续公开摊牌才可用于更新范围。

已撤下的四倍精度候选曾通过 54 组真实浏览器 Worker 与本地完整决策一致检查：六人格、标准/短牌、翻前/翻牌/河牌，以及额外标准目标配置。实际桌面三手核对 50,000 总筹码、100 的普通加注单位、人格和脑保持、无私有字段泄漏、无挂起 Worker。默认算法由相同共享核心执行。新版本地服务握手增加 appVersion，自动启动服务时不复用旧版服务；手动加入他人房间仍由其服务器规则和算法决定。

## 内存与计算代价

默认保留 GPU 加速。v1.5.8 界面复测，在 1280×860 实际滚动 228 像素，658 个有效 rAF 间隔平均 8.43ms、P95 8.40ms、最长 33.3ms，无 >34ms 的间隔；切歌四次文字修改零次、音乐控件几何稳定。rAF 是帧回调读数，不等同于显示器实际 FPS；一次暖缓存测试不是跨机器保证。

内存仍主要由 Electron 的 GPU 进程占用。用新版、两个全新配置目录、同样 1280×860 十人桌场景比较：默认 GPU 进程工作集合计 **977.71 MiB**、Private Bytes **697.49 MiB**；低内存模式工作集 **614.58 MiB**、Private Bytes **234.41 MiB**。工作集求和可能重复计算共享页，不能当整机净独占内存；不同配置和缓存也可能造成变化，未实现无代价大幅降内存。

**低内存模式存在实测代价。** 它关闭 GPU 合成，增加 CPU 绘制：相同滚动脚本，低内存 601 个间隔平均 9.23ms、P95 **16.60ms**、最长 **91.5ms**，四个 >34ms 长帧；GPU 658 个间隔 P95 **8.40ms**、最长 **33.3ms**，无 >34ms 长帧。默认继续 GPU，低内存由用户主动选择。这是本机短测试，不能保证每台设备同样幅度。

四倍采样也有代价：第四轮目标候选平均决策 **27.63ms**、P95 **49.43ms**，基线 **9.74ms**、P95 **18.70ms**。实际 Windows Worker 的 18 个目标样例包含传输及初始化，平均 **27.42ms**、最长 **77.40ms**，均未截断；正常运行在 Worker 中，不占据主页面每个绘制帧。服务器仍同步决策，负载高时可能增加响应等待；异常预算刹车仍保留，强度确认和连续筹码检查须记录采样截断。

其他成本：音乐首次开启可能有加载等待；有限历史丢弃很早的详细记录；为保存全部座位，小窗口保留纵向滚动；固定座位占据稳定高度，换来出手不再让整桌跳动。隐藏的思考点暂停动画；未启用的继续范围、联合付款和人格候选没有进入默认每次决策。

## 复现与边界

Linux 四核最多四个有限工作进程，封存每阶段代码后才运行，不在运行中改算法。没有常驻训练或自动发布。JSON 计划记录种子、人格与盲注；完整基线、源代码快照、JSONL 和失败结果另归档。密码没有写入代码、日志或归档。

过载时的第一次 Linux 全文件并发单测出现时间预算/确定性失败；同时大量比赛、再用单文件并发时仍有一次性能阈值失败。保留原失败日志，在空闲服务器上相同源码顺序执行全部回归通过；没有放宽预算断言。异常负载时间刹车仍可能截断采样，不能保证任何负载下逐决策一致。

第三轮后 Windows 与空闲 Linux 各 127 项回归通过，第四轮各 130 项通过，第五轮 Windows 与 Linux 均 131 项通过，确认候选 Windows 131 项通过。最终确认、兼容、连续筹码和证据哈希在完成后补入本报告。参考来源与完整策略推理见策略实现说明，包括 PokerStars 的开池和 GTO Wizard 的多人底池；这些资料指导设计，强度结论只来自本项目实验。

第六轮工作树 Windows 133 项回归通过；同一候选在 Linux 的 133 项回归也全部通过；第七阶段候选的 Windows 和 Linux 各 136 项通过。相对范围排序只依据当前公开牌面分数及当前听牌，不依据未来模拟胜负。第六轮候选种子 481001，每项 96 块、3072 桌手。

## 第四次独立确认及方法转换

第六轮相对牌力排序加联合付款，独立种子 491001～498001 共 32,768 桌手、1024 洗牌块，均值 **-0.09 BB/100**，名义 95% 区间 **-1.33～+1.15**。累计时间和筛选较好均值不能替代确认；撤下默认组合，不宣称增强。442,182 次决策错误与超时均为零。

第七阶段将搜索终局叶节点先按完整净筹码收益处理：终局跟注不扣未来弃牌风险，不被固定翻前范围或跨街计划盖掉。两个种子 521001、522001 的全下候选筛选合并 +0.84 BB/100，区间 -0.92～2.59；同时处理关闭河牌的候选 +0.79，区间 -0.97～2.56。它们也没有证明强度提升，当前默认开关仍为零。该阶段 12,288 桌手错误/超时为零；诊断计数 `terminalSpots` 因 trace 当时未导出标识为空，不能将空计数当作从未触发。标识已补充，原结果和封存源码不改。

已审阅用户提供的 OpenSpiel 和 luckyone18/Poker 固定源码。参考前者独立实现了离线全树表格式 CFR，按信息集共享策略，并以一致信息集最佳回应计算 NashConv；不加载神经网络。Kuhn 测试计算值 -0.055546，已知值 -1/18，10,000 次迭代的 exploitability 约 .00232。此数字只描述小扑克测试，不能用于证明十人德州强度。进一步的河牌范围原型使用合法组合的卡牌排除、六个私有牌力桶、联合概率和条件终局价值，最多一次再加；它丢失部分桶内阻断信息，尚未加入游戏。Windows 首个河牌案例 1000 次迭代约 2.44 秒，远高于默认十几毫秒；不能不说明代价就接入默认实时 Bot。详细源码核查与收益函数问题见策略调研。

## 当前工作状态（2026-10-08，尚未完成正式 Bot 强度升级）

累计完成 186,880 桌手，包括七阶段候选、四次独立确认、三个被撤下候选的兼容与连续筹码测试。多个候选共享洗牌种子、两次交换座位，因此不能把该总数当成独立样本量。CFR 求解迭代不计入桌手。

当前所有新增策略开关为零，保留 v1.5.7 已验证策略；完整 CFR 原型仅在离线工具中运行。当前工作树 Windows 与空闲 Linux 各 144 项回归通过，实际 Electron 当前默认策略的 54 组 Worker/本地完整结果一致。此前三手几何和 UI 验收属于同一 UI 实现，候选计算被撤下不改变其布局修复；不能把候选通过的桌面检查当作强度证明。

Linux 四核并行完成干燥、连张、对子、三同花四个范围河牌原型，每项 10,000 次有限 CFR 迭代。只在该六桶、单挑、最多一次再加的抽象模型中，相对一致信息集最佳回应的 exploitability 从 2500 次的 3.62～5.21 筹码下降至 10000 次的 1.22～2.07 筹码（初始底池 1000）。四项各耗时约 63～64 秒，含四进程 CPU 竞争。它证明该有限模型的迭代改进，**不是原桌面 Bot 的盈利、十人均衡或职业牌手强度指标**。

正式接入与独立多人验证仍未完成。当前未因新增离线原型让游戏增加实时求解成本；也没有将无优势候选随默认包交付。所有封存源码、基线、成功/失败日志与 JSONL 已归档至 `D:\德州扑克\测试报告\v1.5.8`，标注工作进行中。
