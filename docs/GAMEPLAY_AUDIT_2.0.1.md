# v2.0.1 核心规则与牌桌行动审查

日期：2026-10-25。原版 JS/Electron 及用户设置作为保留资料，不修改原版分支。

## 发现与修正

1. **每轮行动串到下一轮**：原 `last_action` 是整手记录，UI 却把它当作当前轮行动。新增独立 `round_action`，换轮时随 `round_bet` 清零；整手记录继续用于 AI。联机公开快照也改为发送本轮记录。头像分别显示本次支付的金额和本轮总投入；过牌、弃牌不显示无意义的 0。
2. **对全下对手空加注**：只剩一名有筹码玩家时，原版仍允许该玩家向全部全下的对手加注。现在只允许跟注/弃牌（筹码不足时保留跟注式全下），多余下注不能提交。
3. **按键重复入口**：旧全局快捷键通过 `key_pressed` 读取，没有消费事件，事件仍可能触发聚焦按钮，且操作系统长按重复会被当作新行动。现在一帧取一个非重复物理按键并消费相关事件，阻止重复提交；文本输入、设置界面及未打开加注面板时的滑块方向键保留自身行为。
4. **行动可见性**：顶部显示本轮顺序与当前行动者；玩家自己的 D/SB/BB 位置可见，单挑显示 D/SB。小窗口中音乐条不再依赖鼠标悬停才出现。音乐播放/停止、上一首、下一首、音量、顺序/随机/单曲模式及提示音集中在牌桌上方。

## 出手顺序的独立验证

规则依据：[Poker TDA，2026 规则，第 36 条及下注顺序条款](https://www.pokertda.com/view-poker-tda-rules/)。标准德州翻牌前大盲左侧先行动；单挑庄家/小盲先行动。翻牌、转牌、河牌均从庄家左侧第一位仍能行动者开始，跳过已弃牌和全下座位。小盲、大盲均能行动时，小盲先、大盲随后；单挑大盲先。

- `poker-engine/tests/action_order.rs`：2～10 人、全部 54 个庄家位置；每轮完整顺序、大盲翻牌前保留行动权、翻牌后加注返回、弃牌/全下跳位、短全下累计重新开放加注、每轮记录清零及孤立跟注者限制。
- `poker-app/tests/action_order.rs`：正常 `TableConfig` / `TableSession::tick` 路径，2～10 人、每种 6 个种子；检查每个玩家轮次、AI 延迟和单帧仅推进一次，检查每个新轮次从正确座位开始。
- `poker-server/tests/rust_interop.rs`：真实 Rust WebSocket 客户端与服务端对局；单挑翻牌后三轮均大盲先，初始快照没有上一轮记录及金额。
- 原有 `fundamentals`：3,200 手标准/短牌混合行动，检查牌不重复、筹码守恒、合法行动、边池、退款、奇数筹码、短全下与结算幂等。

用户提到的“小盲、大盲仍能行动却由大盲下一位先行动”，在当前源码的上述引擎和正常对局路径中未复现。没有据此声称已定位该现象的唯一根因；已修正可能造成操作重复的输入入口，并让实际顺序、弃牌及全下状态可直接核对。

## 与旧版黄金语料的明确差异

旧 JS 语料包含向全部全下对手多押筹码的脚本动作。回归会明确剔除该场景中的非法加注选项；遇到脚本的终局超额全下时改为合法跟注并要求立刻结算。仅该终局动作的历史标签/支付金额及攻击者历史允许不同，所有牌、轮次、筹码、底池、退款、赢家和派彩仍逐项比较。原版语料和生成脚本不修改，其他场景保持精确比较。

## 验证与交付方式

- Windows x64 MSVC：工作区测试、服务端 integration / phase_b / rust_interop / audit_races、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all --check`。
- 原生窗口检查顶部控件、本轮金额和位置标记；截图与测试配置使用隔离目录，不污染用户设置。
- GitHub 的 Linux/Windows CI、黄金语料重生成及独立 Windows release 构建均通过后，才发布便携包。安装时核对 SHA256，保留 exe 与 assets，桌面快捷方式不附加种子或测试场景参数。
- 测试覆盖不能证明所有可能状态都无缺陷；本报告区分已复现并修正的问题与尚未复现的反馈。
